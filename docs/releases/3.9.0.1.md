# BetterReports 3.9.0.1

Security release for OpenSearch and OpenSearch Dashboards 3.9.0. Upgrade both plugins from 3.9.0.

- **Fixes a memory-exhaustion risk in request validation (High).** Upgrades `zod` from 3.25.76 to 4.6.7 for [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) (CVE-2023-54404). An authenticated user could send a report or schedule body of up to 5 MB whose arrays far exceeded their limits, and the validator recorded an issue for every element. An oversized array is now rejected with a single issue, and a regression test covers it.
- **Removes the vulnerable build-time ZIP dependencies (Medium).** The build no longer uses `archiver`, which pulled in `minimatch` ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)) and `glob` ([GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4)). `archiver` 8.0.0 still depends on an affected `minimatch`, so the plugin ZIP is now written with `yazl`, which has neither dependency. These packages ran only during the build and were never shipped in the plugin.
- **Pins `@opensearch-project/opensearch` to exactly 3.6.0.** The previous `^3.5.1` range would have admitted the malicious 3.6.2, 3.7.0, and 3.8.0 releases ([GHSA-27f5-xjrr-q9ff](https://github.com/advisories/GHSA-27f5-xjrr-q9ff)) if the lockfile were ever regenerated. The shipped version is unchanged.
- Validation error messages returned with HTTP 400 use zod 4 wording (for example `Too big: expected array to have <=100 items`). The `VALIDATION_FAILED` code and the accepted request formats are unchanged.
- Patch releases add a fourth number to the platform version, like other OpenSearch plugins. 3.9.0.1 still supports exactly OpenSearch and OpenSearch Dashboards 3.9.0.
- No changes to report storage, grants, roles, or configuration keys. Existing reports, schedules, and authorizations carry over unchanged.

To upgrade from 3.9.0, remove and reinstall both plugins with the 3.9.0.1 ZIPs (or switch to the `3.9.0.1` container images), restart, and hard-refresh the browser. See [Deployment](../DEPLOYMENT.md#upgrading-to-3901).
