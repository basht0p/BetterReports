# BetterReports 3.9.0

- Supports OpenSearch and OpenSearch Dashboards 3.9.0, with Security, Notifications, and Notifications Core 3.9.0.0.
- BetterReports versions now match the OpenSearch and OpenSearch Dashboards version they support, like other OpenSearch plugins. This release follows 0.1.2 and includes all of its features. Each release supports exactly the platform version in its number.
- Reads each user's Advanced Settings (date and number formats) from the current Dashboards version's settings object. The previous code requested the 3.8.0 object by name, which would have ignored those settings after an upgrade.
- Adds saved searches as report sources. Choose a saved search in the builder, from a dashboard's saved-search panel, or with **Share → Create BetterReport** in Discover. Its matching documents render as a full-width table using the saved columns and sort order, with at most **1,000 rows**. Each report can choose a lower limit; when more documents match, the PDF states the total. Organization scope, DLS, and FLS apply to every row. See [Supported sources](../SUPPORT.md).
- The OpenSearch companion now accepts saved-search document queries of up to 1,000 rows, alongside aggregation queries. Upgrade the companion on every node together with the Dashboards plugin.
- Raises the default page ceiling (`better_reports.limits.pages`) from 20 to 60 so a 1,000-row table fits, and allows up to 250. Deployments that set it explicitly keep their value.
- Publishes container images with the plugins installed: `ghcr.io/basht0p/betterreports-opensearch:3.9.0` and `ghcr.io/basht0p/betterreports-dashboards:3.9.0`. See [Deployment](../DEPLOYMENT.md#container-images).
- No changes to report storage, grants, roles, or configuration keys. Existing reports, schedules, and authorizations carry over unchanged.

OpenSearch 3.8.0 and Dashboards 3.8.0 are not supported by this release; continue to use 0.1.2 on 3.8.0. To upgrade, remove both 0.1.2 plugins, upgrade the platform to 3.9.0, then install both 3.9.0 plugins together and hard-refresh the browser. See [Deployment](../DEPLOYMENT.md#upgrading-to-390).
